# Blocky: редактор схем с ИИ-ассистентом

**Статус:** мой продукт на ранней стадии. Закрытый репозиторий, деплоя и пользователей пока нет.

## Задача
Процессы и воронки рисуют квадратиками и стрелками, но такая схема не показывает, что будет, если пустить через неё числа. Мне нужен был редактор, где схему можно запустить, а ассистент предлагает правки, которые пользователь принимает или отклоняет.

## Что сделал
- **Редактор на канвасе.** Блоки, порты, связи и зоны на Konva. Preact, @preact/signals, SCSS/BEM, TypeScript, Vite.
- **Симуляция.** Числовые сигналы проходят по схеме.
- **Предложения ИИ.** Пользователь описывает правку словами, ассистент возвращает новую схему целиком. Ничего не меняется, пока пользователь не примет.
- **Прокси к Groq с лимитом на пользователя.** Браузер не обращается к провайдеру напрямую. Бэкенд на Hono отправляет запросы в Groq (по умолчанию Llama 3.1 8B Instant). У каждого пользователя месячный лимит вызовов модели, сверх лимита API отвечает 429. Без корректного лимита сервер не стартует, без ключа работает в режиме заглушки.
- **Бэкенд.** Hono на Node, Postgres 16, общие zod-контракты в `shared/` для клиента и сервера, регистрация по инвайтам, argon2, сессии на HMAC-cookie.

## Как работал
Я настраиваю и запускаю агентов (Cursor, Grok Bot). Я проектирую и пишу спеки, агенты Cursor пишут код, я проверяю и мержу. После каждого смерженного PR QA-агент забирает `main`, поднимает стек локально, тестирует изменения в браузере и заводит issues с метками. Агенты Cursor их чинят, я мержу.

## Результаты
- 18 сентября 2026 QA-агент до обеда завёл issues #12 по #17 (2 бага, 4 улучшения). Агент Cursor исправил все шесть в PR #18 (23 файла, +162/-40), я смержил его в 14:38 того же дня. Повторный тест примерно через 20 минут подтвердил исправления и нашёл новый баг (#19).
- Репозиторий создан 8 сентября 2026, с 16 по 18 сентября смержено 11 PR.
- На каждом PR две обязательные проверки в GitHub Actions: установка, typecheck и сборка, плюс смоук-тест Playwright (3 теста на локальном Vite). На `main` обе зелёные. В `main` только через PR, без force-push.
